# Project Guidelines

## Environment
- Language: 日本語で対話・コメント記述

## Core Principles（優先順）
1. 安全第一: 許可なく破壊的操作を行わない。迷ったら確認する。
2. シンプル第一: 変更は最小限に。影響範囲を狭く保つ。
3. 根本解決: 応急処置ではなく原因を解決する。

## Safety
- 全 Bash コマンドはユーザーの許可を得てから実行する。
- 作業ディレクトリ外へのアクセスは行わない。
- 大きなファイルは分割処理（バッチ100件目安）。
- ファイル読み込み前にサイズ確認: `ls -lh`
- 長時間ループには安全カウンタを設置する。

## Data Flow
- Input: ./input/
- Output: ./output/
- Work: ./workspace/

## Workflow
- 3ステップ以上または設計判断を含むタスク → PLANNING_FLOW.md に従う。
- 単発の質問・閲覧のみ・自明な単一コマンド → 直接実行してよい。
- 問題が起きたら停止し、ユーザーに報告して再計画する。
- 実装前に仕様を明文化する。曖昧なまま着手しない。
- 動作確認なしに完了扱いにしない。検証方法を提示し承認後に実行する。
- ハックっぽい修正になった場合は正直に報告し、より良い方法を提案する。

## Sub-agents
- 調査・探索・分析に限定して使用する。
- 委任内容をユーザーに事前に伝える。
- サブエージェントにファイル変更・削除・外部通信を行わせない。

## Package Installation
外部パッケージのインストール時、以下を必ず実行する。

提案時の義務（省略不可）：
1. パッケージ名・バージョンを明示し、公式URLを添える。
2. 正規パッケージの正式名称と提案名が一致することを確認する。
3. なぜ必要か、標準ライブラリで代替できないかを説明する。
4. 報告フォーマット:
   パッケージ: <名前>@<バージョン> / 公式URL: <URL>
   名称確認: ✓一致 or △未確認 / 用途: <一文>

コマンド構成の義務（省略不可）：
- npm: `--ignore-scripts` を付ける。
- バージョンを固定する。
- 一度に一つずつインストールする。

禁止事項：
- curl <URL> | bash
- 名称確認が未完了のままインストール提案すること

詳細な背景と限界の説明 → PACKAGE_PROTOCOL.md
