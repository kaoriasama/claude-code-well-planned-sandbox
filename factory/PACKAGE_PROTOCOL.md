# Package Installation Protocol

外部パッケージのインストール（npm install, pip install, brew install 等）を
行う場合、以下の手順を必ず踏む。

## Step 1: 必要性の検証（Claudeの責務）

- なぜこのパッケージが必要か説明する。
- 標準ライブラリや既存の依存で代替できないか検討した結果を示す。
- 代替できる場合はインストールしない方針を提案する。

## Step 2: パッケージの同定（Claudeの責務）

パッケージ名を提案する際、以下を必ず実行する。

1. 公式リポジトリURL を明示する。
   - npm: `https://www.npmjs.com/package/<パッケージ名>`
   - PyPI: `https://pypi.org/project/<パッケージ名>`
2. 正規パッケージの正式名称を公式ドキュメントから引用する。
3. 提案するパッケージ名と正式名称が一字一句一致することを確認する。
4. 類似名のパッケージが存在する場合、その旨を警告する。

報告フォーマット：

```
パッケージ: <名前>@<バージョン>
公式URL: <URL>
名称確認: 公式ドキュメントの記載と一致 ✓ / 未確認 △
用途: <一文>
週間DL数: <概算（わかる場合）>
```

## Step 3: インストールコマンドの構成（Claudeの責務）

- バージョンを固定する（`package@1.2.3`）。
- npm の場合 `--ignore-scripts` をデフォルトで付ける。
  正常動作に必要な場合は理由を説明の上フラグなしを提案する。
- 複数パッケージを一度にインストールせず一つずつ提案する。

## Step 4: ユーザーの判断

以下の場合は拒否を推奨する。

- 名称確認が「未確認」のまま。
- 公式URLが提示されていない。
- 判断に迷う場合。

## 原則

- 依存パッケージは必要最小限にする。
- 公開1ヶ月未満のパッケージは避ける。
- `npx` も同等の検証を行う。
- `curl <URL> | bash` パターンは原則禁止。

## このプロトコルの限界

- Claude の知識の鮮度に依存する。訓練データ以降の悪意あるパッケージは検知できない。
- 公式URLの提示は Claude の知識に基づく。最終的にはユーザーが確認するのが最も確実。
- 正規パッケージのメンテナーが乗っ取られた場合は防げない。
  バージョン固定と --ignore-scripts で軽減するが完全ではない。
